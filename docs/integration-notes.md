# 小屏幕与助手 / SignalRGB 联动

已安装 Codex 和 助手 B 状态钩子、CodexLCD 本地灯效。
配置备份位于 %APPDATA%/GpuLcdTool/integration-backups/20261007-001205。

## 使用

保持小工具在托盘运行。“联动”页分别开关 Codex、助手 B 和 SignalRGB。
SignalRGB 选中免费本地灯效 CodexLCD；“打开 SignalRGB 灯效库”按钮可打开选择页面。
工作为蓝色，等待操作为橙色，本轮结束为绿色。Codex 结束提示 30 秒，助手 B 保留 120 秒。
结束后恢复默认动画；多个任务并行时等待操作优先，然后工作，最后结束提示。
“本轮结束”不代表任务成功。30 分钟没有事件的状态自动过期。

## DeepSeek Harness 来源协议

GpuLcd 汇总 Codex、Claude Code 和 DeepSeek Harness 的会话状态，再统一转发给 LCD、SignalRGB 和 Dot Matrix Studio。DSH 插件不要同时直发第二路点阵画面，以免绕过汇总优先级并抢屏。

| 来源 | 工作 / 等待 / 结束事件 | SignalRGB 配色 | 结束提示时长 |
| --- | --- | --- | --- |
| Codex | `working` / `waiting` / `done`（保留裸事件） | 原蓝色 / 橙色 / 翠绿呼吸 | 30 秒 |
| Claude Code | `claude@working` / `claude@waiting` / `claude@done` | 原陶橙 / 琥珀呼吸 / 草绿渐亮 | 120 秒 |
| DeepSeek Harness | `dsh@working` / `dsh@waiting` / `dsh@done` | 深蓝 `#4D6BFE` / 橙金 `#FF9F45` / 青绿 `#2ED3B7` | 30 秒 |

灯效接受原文及 URL 编码事件，发送者仍必须为 `GpuLcdTool`。非空闲状态按来源配色；同状态切换来源也会生效，同来源的结束心跳不重启动画。`idle`、`idle@epoch@offset[@percent]`、`sleep` 和 `wake` 协议不变，熄灯始终优先于任务和手动预览。

回执保留 `GpuLcdState=状态;seq=序号` 旧格式；Claude/DSH 追加 `;client=claude` 或 `;client=dsh`。GpuLcd 连同来源一起去重并显示确认来源；不带来源的旧回执仍表示 Codex。

DSH 事件的 `UserPromptSubmit` 可带 `state: "waiting"`，一次替换旧轮次并直接进入等待，供插件恢复丢失的启动事件；不必先发 working 再发等待。`state` 省略、空值（含 null）或 `"working"` 沿用工作启动，其他非空值拒绝该次 DSH 启动。此扩展仅对 `client: "dsh"` 的启动事件有效，其他客户端和非启动事件忽略它；原有非启动事件的轮次与关闭检查、优先级和 15 秒来源保持规则不变。

事件入口只接收精确小写的 `codex`、`claude`、`dsh`。未知来源、大小写变体、空字符串和显式 null 均不落入 Codex；旧事件省略 `client` 字段时仍使用默认 Codex。关闭某客户端会清除其已合并状态，重新开启只接收新事件，不恢复旧任务。相同优先级的显示来源至少保持 15 秒；等待优先于工作，工作优先于结束。

此修复仅通过离线状态机、脚本渲染和设置合并测试验证，未连接真实灯光或屏幕。部署仍需另行安装新版 GpuLcd、更新 SignalRGB 本地模板，并在用户许可下验证真实事件与设备输出；本次不修改真实 DSH profile、不重启应用、不上传屏幕。

## 双向连接

小工具通过 SignalRGB 官方 16034 事件接口发送状态，灯效脚本打印带序号的接收确认。
小工具通过 SignalRGB MCP 的只读接口读取当前灯效、设置和确认日志。
SignalRGB 中 Preview / LCD test 的 Working / Waiting / Done / Idle 可反向触发屏幕预览，持续 8 秒。
Auto 表示跟随事件。当前预览选项要改变一次才会再次触发。
这是一组状态的联动，不是将任意 SignalRGB 灯效逐帧投屏。

不再使用原计划的 19347 本机 HTTP 回传口：SignalRGB 灯效网页禁止访问不安全 HTTP，故改用 MCP 读取。
没有改动浏览器安全设置，也没有绕过 Pro 限制。MCP 自动应用灯效要求 Pro，因此通过正常界面选择本地灯效。
助手消息正文、提示词和工具参数不记录、不转发；钩子仅转发事件类型、会话和回合标识。
不改变原 Codex notify，不修改 Codex 信任记录。若 Codex 提示审阅，可在 /hooks 查看这份钩子。

## 默认动画与灯效时间对齐（2026-10-07）

速度校准：联动页增加“灯效播放速度（%）”，默认 100.00%，范围 95–105%，步长 0.01%。起始偏移只修正固定延迟；若对齐后逐渐偏离，可降低速度修正灯光领先、提高速度修正灯光落后。改速后重新播放并对齐，再观察多个循环。IdleRatePercent 独立保存，原偏移保留；未测量前不自动改变速度。新版事件为 idle@epoch@offset@percent，灯效仍兼容旧三段事件。相位计算为 elapsed×rate+offset，20 秒心跳不重置进度。

例：原速下 300 秒积累 0.3 秒领先，可先试 99.90%；同幅落后可先试 100.10%。这是基于匀速漂移的近似，若偏差忽前忽后或随机跳变，不应持续用调速追赶。当前未能读取屏幕实际播放帧，SAVI 标称时长不能证明硬件循环正好等长。模拟十分钟漂移、偏移独立性、心跳、旧协议及界面渲染检查通过；实物速度修正需测量。

默认 img1.savi 的本地上传副本头部为 554 帧、60 fps，循环 9233.333 毫秒。灯效配色已从该 SAVI 的 183 个独立 JPEG 画面提取，按帧索引播放，不再用原始 GIF 的 9250 毫秒周期。画面翻转按转换器的 hflip/vflip 还原后取左右区域配色。

小工具成功发送默认动画播放指令后记录系统时间，通过 idle@播放时间戳@偏移毫秒 事件传给 SignalRGB。灯效使用同一时间基准，即使事件晚到或灯效重载，也会追到对应相位。SignalRGB 当前会原样转交 URL 编码的事件文字，脚本先解码再校验。工作、等待、完成灯效保持原样。

联动页增加“默认灯效时间偏移（毫秒）”：正数让灯光提前，负数让灯光延后，每步 50 毫秒。点击“重播默认动画并对齐”可预览 30 秒，然后恢复助手状态。设备执行播放指令的实际时刻、LCD 的播放速率和 LED 输出延迟无法从现有厂商接口读取，故共享指令时间并不保证物理逐帧同步；需要观察实物校准。若换了默认动画，需重新提取配色与周期。

验证：SAVI JPEG 画面实际解码成功；脚本的延迟传递、循环边界、偏移和 URL 编码测试通过；实机 SignalRGB 日志出现 GpuLcdSync=时间戳;offset=0。物理同步效果等待用户确认。
### 配色修正：保留白色、黑色和空间分布
用户确认主要问题为“切换时间接近，但灯光颜色不像画面”。旧方案排除低饱和度/暗色像素、只选左右两种显著颜色，导致白底消失、黑底被小块彩色覆盖。现已改为 SAVI 每帧缩小到 16×4，共 64 个区域的面积平均 RGB，不排除白色与黑色，再映射到 SignalRGB 画布。保留原来的播放时钟、偏移和亮度系数。灯具在 SignalRGB 布局中的位置决定采样的画面区域，不是每个设备都显示全屏平均色。
脚本时序、状态、64 区域、白色及暗部保留测试通过；软件结果不替代物理灯具颜色的用户确认。
